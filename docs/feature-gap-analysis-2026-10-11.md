# KnowledgeHub 个人知识库能力差距分析与功能补充建议

- 分析日期：2026-10-11
- 参照：LocalMind 项目规划（本地优先 PKM 桌面应用）+ Obsidian / Logseq / 思源笔记 / Joplin / Notion / Flomo / Anki 等同类产品的成熟形态
- 方法：**先核实代码，再下结论**。本文所有"现状"判断均来自对 `backend/app/` 与 `frontend/src/` 的实际检索，而非推测。

---

## 一、核心结论

> **KnowledgeHub 目前是一个「只读的检索 + 问答系统」，还不是一个「可写的个人知识库」。**

它把「文档」当作外部导入的只读语料，围绕这些语料做了检索、问答、知识加工和学习辅助——
但个人知识库的第一性需求是**记录自己的想法**，而这条路径在当前代码里是**断的**。

判断依据（PKM 的三个闭环，一个都没闭合）：

| 闭环 | 应有的链路 | 当前断点 | 代码证据 |
|---|---|---|---|
| **写入闭环** | 新建/编辑笔记 → 保存到 Markdown → 更新索引 → 可检索 | **断在「编辑」** | `frontend/src/components/` 只有 `MarkdownView.vue`（只渲染）与 `MermaidDiagram.vue`，**没有任何编辑器**；`DocumentDetailView` 只能改标题/分类/标签；新增内容唯一入口是「上传文件」 |
| **关联闭环** | 笔记 → `[[双链]]` → 反向链接 → 发现关联 | **断在「链接」** | 全项目检索 `note_links / backlink / wiki_link / [[` → **零命中** |
| **复习闭环** | 学习 → 生成闪卡 → 间隔复习 → 掌握沉淀 | **断在「闪卡」** | `learning_service` 只有出题/评分/错题本，**无闪卡表、无复习排期算法** |

三个闭环都断在中段，于是产品的真实体验退化成：
**「上传资料 → 搜索 → 问 AI」**。这就是它"不像一个易用的个人知识库"的根本原因——
它很好用，但它是**知识消费工具**，不是**知识生产工具**。

### 附带发现：几个"看起来有、实际是死代码"的能力

| 能力 | 现状 |
|---|---|
| 附件管理 | `settings.attachments_path` 已在配置、备份、数据统计中引用，但**没有任何上传/关联代码**——附件目录永远是空的 |
| 编辑正文 | `PUT /api/documents/{id}` 支持 `content_text`，但**既不写回磁盘 `.md`、也不重建索引**——改了就与原文和检索结果脱节 |
| 多级分类 | `Category` 模型**无 `parent_id`**，只有单层平铺分类 |
| 外部变更检测 | `backend/app/` 内检索 `watchdog / watchfiles / awatch` → **零命中**（`run.py` 也没有启动扫描） |

## 二、差距矩阵（现状 vs 典型 PKM）

图例：✅ 已具备 · ⚠️ 部分具备 · ❌ 缺失

| 能力域 | 具体能力 | 现状 | 典型 PKM 的做法 |
|---|---|---|---|
| **录入** | 新建笔记 | ❌ 只能上传文件 | 一键新建，默认落 Inbox |
| | Markdown 编辑 | ❌ 无编辑器 | CodeMirror/Tiptap，所见即所得 |
| | 自动保存 | ❌ 无 | 防抖自动保存 + 崩溃恢复 |
| | 每日笔记 | ❌ | 一键创建当天笔记 |
| | 模板 | ❌ | 技术笔记/复盘/读书/面试模板 |
| | 回收站 | ❌ 硬删除，文件立即 unlink | 软删除 + 可恢复 + 保留期 |
| | 版本历史 | ❌ | 快照 + 差异对比 + 回滚 |
| **整理** | 多级文件夹 | ❌ 单层分类 | 树形目录，可拖拽 |
| | 收藏/置顶 | ❌ `Document` 无对应字段 | 星标 + 置顶区 |
| | 最近访问 | ❌ 无 `last_viewed` | 最近列表 + 继续上次 |
| | 收集箱 | ❌ | 未分类内容的暂存区 |
| **检索** | 全文检索 | ✅ pg_trgm + 关键词 | FTS5 / 倒排索引 |
| | 语义检索 | ✅ pgvector | 向量库 |
| | 混合检索 | ✅ α=0.3/β=0.7 | 关键词 + 向量融合 |
| | 结果高亮 | ❌ snippet 是纯文本，无 `<mark>` | 命中词高亮 |
| | 排序/筛选 | ⚠️ 仅分类+标签 | 时间/相关度/类型/日期区间 |
| | 快捷搜索 | ❌ 无 Ctrl+K | 全局命令面板 |
| | 中文分词 | ⚠️ 2-gram 权宜 | jieba / bigram 专业方案 |
| | 模糊/容错 | ❌ | 编辑距离 / 拼音 |
| **关联** | 双向链接 | ❌ | `[[wiki]]` + 自动补全 |
| | 反向链接 | ❌ | 面板展示"谁引用了我" |
| | 相关笔记 | ⚠️ 有 API，但没进笔记页 | 侧栏常驻 |
| | 知识图谱 | ❌ | 关系网络可视化 |
| **编辑/展示** | 实时预览 | ⚠️ 只能看渲染结果，不能编辑 | 分栏 / 即时渲染 |
| | 大纲面板 | ❌ | 标题树跳转 |
| | 图片/附件 | ❌ 目录是死代码 | 拖拽上传 + 引用 |
| | 代码高亮 | ✅ highlight.js | 同 |
| **导入导出** | 单篇导出 | ⚠️ 只返回 JSON 文本，不落盘 | 导出为文件 |
| | 整库导出 | ❌ | 一键导出全部 Markdown |
| | 目录结构保留 | ❌ 上传即扁平化，原始路径丢失 | 保留相对链接与目录树 |
| | PDF/DOCX | ✅ pypdf / python-docx | 同 |
| | OCR | ❌ | 可选本地 OCR |
| | 备份恢复 | ⚠️ 上轮已修缺表/顺序/穿越，但**真实往返未验证** | 完整性校验 + 恢复演练 |
| **体验** | 工作台 | ⚠️ 有视图，但无"最近/待整理/今日复习" | 打开即见待办 |
| | 快捷键体系 | ❌ | 全局 + 编辑器内 |
| | 三栏布局 | ❌ 无笔记页三栏 | 导航/列表/内容 |
| | 页内呼出 AI | ❌ 必须切到问答页 | 选中文字即问 |
| | 主题 | ⚠️ 仅浅色 | 明暗跟随系统 |
| **隐私** | 单篇 AI 开关 | ❌ `Document` 无 `ai_enabled` | 私密笔记检索阶段即排除 |
| | 网络访问透明 | ⚠️ 有开关，但无"本次是否外发"的明确提示 | 明确区分本地/外部请求 |

## 三、分领域功能建议

> 优先级定义：**P0 = 不做就不算个人知识库**（写入闭环）；**P1 = 决定"好不好用"**；**P2 = 锦上添花**。

### 3.1 知识录入与整理

| 优先级 | 建议 | 解决的实际问题 | 落点 |
|---|---|---|---|
| **P0** | **新建笔记 + Markdown 编辑器**（CodeMirror 6 或 Tiptap，含标题/列表/表格/代码块/任务清单，实时预览） | 当前**根本无法记录自己的内容**——这是"不像知识库"的第一原因。用户只能导入别人的文件，无法沉淀自己的踩坑记录 | 新增 `POST /api/notes`（无文件、只传标题/正文）+ `frontend/src/views/NoteEditView.vue` |
| **P0** | **正文写回磁盘 `.md` 并同步重建索引** | 现在 `PUT` 改 `content_text` 后：磁盘 `.md` 未变、chunks 未重建 → 检索到的还是旧内容，且"Markdown 可迁移"的承诺失效（导出/迁移拿到的是旧文件） | 在 `document_service.update_document` 中：写回 `files.abs_path()` + 触发 `build_index`（异步任务队列） |
| **P0** | **回收站（软删除）** | 现在 `DELETE` 是硬删 + 立即 unlink 原文件，**误删无法恢复**。这是 PKM 最不可接受的体验 | `Document` 加 `deleted_at`；删除改为标记；列表默认过滤；提供「回收站」页 + 彻底删除 |
| **P0** | **收集箱（Inbox）** | 想法往往是零碎的，强迫先分类会打断记录。当前无暂存区，用户只能"先随便传上去" | 默认分类「收集箱」+ 工作台「待整理」区 |
| **P1** | **多级文件夹（分类加 `parent_id`）** | 单层分类在资料超过几十份后立刻失控；且无法与磁盘目录对应 | `Category.parent_id` + 迁移 + 树形组件；或直接镜像 `data/documents/` 目录结构 |
| **P1** | **每日笔记** | 零散记录缺少天然的落点；复盘类内容需要按日期归档 | 侧栏「今日」入口，自动创建 `YYYY-MM-DD.md` |
| **P1** | **笔记模板**（技术笔记/项目复盘/读书笔记/面试记录） | 每次新建都要重写结构，降低记录意愿 | `data/templates/*.md` + 新建时选择 |
| **P1** | **版本历史（正文快照）** | 编辑覆盖后无法回退；当前只有"重建索引"，没有内容历史 | 新增 `note_revisions` 表（content + 时间 + 差异），编辑器提供历史面板 |
| **P2** | 批量导入保留目录结构 | 现有上传是扁平落盘（`uuid.hex` 重命名），原始路径丢失，无法还原知识体系 | 上传时记录 `original_relpath`，支持按目录重建分类 |

### 3.2 内容分类与检索

| 优先级 | 建议 | 解决的实际问题 | 落点 |
|---|---|---|---|
| **P0** | **检索结果高亮** | 当前 `snippet` 是纯文本截断（`retriever.py` 里 `.replace("\n"," ")`），用户要自己在一段文字里找命中词，效率极低 | 后端返回命中词位置或 `<mark>` 标记；前端渲染高亮 |
| **P0** | **排序与筛选**（相关度/更新时间/创建时间 + 分类/标签/日期区间/文档状态） | 现在只有"分类 + 标签"两个过滤维度，且排序固定；资料一多就无法收敛 | `SearchRequest` 增加 `sort`/`date_from`/`date_to`/`status` |
| **P0** | **全局快捷搜索（Ctrl+K）+ 键盘导航** | 找东西要「点侧栏 → 进检索页 → 输入 → 回车」四步；PKM 的标准是两秒内打开目标 | 全局命令面板组件（搜索 + 跳转 + 新建） |
| **P1** | **中文分词专项** | 现用中文 2-gram（`rag/tokenize.py`），单字词、专有名词、短查询命中率差；这直接决定中文检索体验 | 评估 `jieba` 预分词后建 pg_trgm/GIN，或 `pg_bigm`；用中文测试集验证 |
| **P1** | 模糊/容错搜索 | 记不清确切用词时搜不到，是"找不到以前记录"的主因 | 编辑距离 / 拼音首字母 / 同义词扩展 |
| **P2** | 重排序（rerank） | 混合检索的 top-k 里仍可能有噪声 | 交叉编码器或 LLM 精排 |

### 3.3 标签与关联

| 优先级 | 建议 | 解决的实际问题 | 落点 |
|---|---|---|---|
| **P1** | **双向链接 `[[笔记名]]` + 反向链接面板** | 知识之间只有"检索"这一条发现路径，缺乏**语义关联**；这是 Obsidian/Logseq 的核心价值，也是"知识网络"与"文件堆"的分水岭 | 编辑器内 `[[` 自动补全；新增 `note_links` 表；笔记页侧栏「反向链接」 |
| **P1** | **相关笔记常驻笔记页** | `GET /api/insights/related/{id}` 已实现，但只在「知识加工」页里，用户在读笔记时看不到 → 好功能被埋没 | 把 related 结果接入 `DocumentDetailView` 侧栏 |
| **P1** | **标签增强**（层级 `父/子`、颜色、重命名传播、合并重复） | 现在标签只有 CRUD；`tag_service` 有 `similar` 但无合并入口，标签会越用越乱 | 标签管理页增加「合并」「重命名并传播」；标签支持颜色与分组 |
| **P2** | 知识图谱 | 需要双向链接做前置数据，否则只能按分类画星形图，价值有限 | 依赖 3.3 的第一项 |

### 3.4 笔记编辑与展示

| 优先级 | 建议 | 解决的实际问题 | 落点 |
|---|---|---|---|
| **P0** | **编辑器三件套**：编辑/预览切换、大纲面板、代码高亮（已有） | 长笔记没有大纲就只能靠滚动；没有编辑/预览切换就无法边写边核对排版 | 编辑器 + `OutlinePanel.vue` |
| **P1** | **自动保存防抖 + 冲突处理** | 计划里明确点名的问题：自动保存不能反复覆盖新输入；外部改了同一个文件不能静默丢弃任何一份 | 编辑器 800ms 防抖 + `updatedAt` 乐观锁 + 冲突时并排对比 |
| **P1** | **外部变更检测（启动扫描 + 定时哈希比对）** | 用 VS Code / Typora 直接改 `.md` 是高频场景；当前无监听器、无扫描 → 库与磁盘会长期不一致 | 启动时按 `file_size + mtime + sha256` 比对，差异进 `index_jobs` 重试队列 |
| **P1** | **图片/附件上传与引用** | 附件目录是死代码，笔记里放不了图，技术笔记的截图无处安放 | 复用 `attachments_path`：`POST /api/attachments` + 编辑器粘贴上传 + Markdown 引用 |
| **P2** | 块级引用/嵌入（`![[笔记#段落]]`） | 高阶复用能力 | 依赖双向链接 |

### 3.5 数据导入导出

| 优先级 | 建议 | 解决的实际问题 | 落点 |
|---|---|---|---|
| **P0** | **整库导出为 Markdown 目录树** | 现在只能单篇导出，且 `export_document` **只返回 JSON 文本、不写盘**（`files.write_export` 甚至没被调用）——所谓"可迁移"目前是口号 | `POST /api/export/all` → 打包 zip 落盘 `data/exports/` |
| **P0** | **备份/恢复真实往返验证** | 上一轮已修「缺 glossary/quiz 表 + 父子块顺序 + Zip Slip」三个 P0，但**破坏性往返测试一直因库中有数据而跳过**，实际可用性未经证实 | 空库环境跑 `tests/test_backup.py`；补「恢复后检索仍可用」断言 |
| **P1** | 导入保留目录结构与相对链接 | 现有上传扁平化，导入一个知识库会丢掉全部层级和图片相对路径 | 支持 zip/文件夹上传，记录 `original_relpath`，重写相对链接 |
| **P1** | PDF/DOCX/HTML 解析质量 + 来源元数据 | `parsers.py` 已能提取文本，但 PDF 丢版式、DOCX 丢层级关系；HTML 走纯文本会丢结构 | 保留页/标题层级；HTML 转 Markdown 而非纯文本 |
| **P2** | 扫描版 PDF OCR | 扫描件现在直接 `ParseError`（提示需 OCR），用户无路可走 | 可选接入本地 OCR（Tesseract/PaddleOCR） |

### 3.6 使用体验

| 优先级 | 建议 | 解决的实际问题 | 落点 |
|---|---|---|---|
| **P0** | **工作台补齐「最近编辑 / 待整理 / 今日复习」** | 打开应用第一眼应该看到"我该做什么"，而不是一个静态欢迎页 | `WorkbenchView` 接 `recent` / Inbox 计数 / 待复习数 |
| **P0** | **收藏与置顶 + 最近访问** | 常用笔记（如自己的速查表）每次都要搜，违背"个人知识库"的直觉 | `Document` 加 `is_pinned` / `is_favorite` / `last_viewed_at` |
| **P1** | **快捷键体系 + 三栏布局** | 桌面知识库的效率来自键盘；现在全靠鼠标点侧栏 | `Ctrl+K` 搜索、`Ctrl+N` 新建、`Ctrl+S` 保存、`Ctrl+Enter` 预览 |
| **P1** | **笔记页内直接呼出 AI** | 现在必须切到「AI 问答」页再手动把内容粘过去；计划里明确要求"选中文字 → 解释/总结/出题/找关联" | 编辑器浮动工具条 → 调 `/api/insights/*` 与 `/api/learning/questions` |
| **P1** | 明暗主题 | 长时间写作只有浅色伤眼 | CSS 变量已按 `--kh-*` 组织，接 `prefers-color-scheme` 成本低 |
| **P2** | 学习中心（闪卡 + 间隔复习 SRS + 统计） | `quiz_records` 已有作答记录，但没有"卡片 + 排期"这一层，知识无法沉淀为长期记忆 | 新增 `flashcards` / `review_logs` 表 + SM-2 排期 |

### 3.7 跨领域：隐私（必须补）

| 优先级 | 建议 | 解决的实际问题 | 落点 |
|---|---|---|---|
| **P0** | **单篇笔记 AI 开关（`ai_enabled`）** | 计划里明确要求：**「标记为不允许 AI 读取的笔记，检索阶段就必须排除，而不是只在提示词里提醒模型忽略」**。当前 `Document` 无该字段，私密笔记会照常进入 RAG 上下文 | `Document.ai_enabled` + `retriever` 的 SQL 过滤 + 设置页默认值 |
| **P1** | 网络访问透明提示 | 已有 `WEB_SEARCH_ENABLED` 双开关，但界面没有"本次请求是否离开本机"的明确标识 | 问答页显示「本次：本地模型 / 已外发联网」标识 |

## 四、优先级路线图

```
第 1 批（写入闭环，缺一不可）
  ├─ 新建笔记 + Markdown 编辑器
  ├─ 正文写回磁盘 + 重建索引
  ├─ 回收站（软删除）
  ├─ 收藏/置顶/最近访问
  └─ 单篇 AI 开关（隐私）
        ↓ 有了这一批，它才第一次成为"可用的个人知识库"

第 2 批（好用）
  ├─ 检索高亮 + 排序筛选 + Ctrl+K 快捷搜索
  ├─ 收集箱 + 工作台（最近/待整理）
  ├─ 大纲面板 + 自动保存防抖 + 外部变更扫描
  ├─ 图片/附件上传
  └─ 整库导出 + 备份恢复真实往返验证
        ↓ 有了这一批，日常使用才不别扭

第 3 批（知识网络与沉淀）
  ├─ 双向链接 + 反向链接面板 + 相关笔记进笔记页
  ├─ 多级文件夹 + 每日笔记 + 模板 + 版本历史
  ├─ 中文分词专项 + 模糊搜索
  └─ 笔记页内呼出 AI

第 4 批（进阶）
  ├─ 闪卡 + 间隔复习 + 学习统计
  ├─ 知识图谱 + 块级引用
  └─ OCR + 重排序 + 目录结构导入导出
```

---

## 五、最小可行补丁（不改架构就能显著改善体验的 5 件事）

若想用最小成本让它"立刻像个人知识库"，按投入产出比排序做这 5 件：

1. **`POST /api/notes` + 一个简易编辑器页**——打通写入，这是 0→1 的一步。
2. **`update_document` 写回磁盘 + 重建索引**——让"编辑"真正可信（当前改了等于没改）。
3. **软删除 + 回收站页**——消除"误删就没了"的恐惧，PKM 的信任基础。
4. **检索结果高亮 + Ctrl+K**——让"找得到"变成两秒内的事。
5. **`Document.ai_enabled` + 检索层过滤**——隐私是本地知识库的卖点，缺了它卖点不成立。

这 5 项合计约新增 2 张表（`note_revisions` 可选、`Document` 加 4 个字段）、3 个端点、2 个前端页面，**不触碰现有 RAG/检索架构**。

## 六、一个必须先做的战略决策

LocalMind 规划的是 **Electron + React + SQLite + LanceDB + Ollama**；
而 KnowledgeHub 现状是 **Web + Vue3 + FastAPI + PostgreSQL/pgvector + 外部 API（当前接的是通义千问）**。

两者不是"加功能"的关系，而是**两套技术栈**。所以在动手前必须先定：

| 选项 | 适用条件 | 代价 |
|---|---|---|
| **A. 在 KnowledgeHub 上补功能** | 认可"浏览器打开 + 本机 PostgreSQL"的形态；不想重写 | 需补：编辑器、软删除、双链、附件、文件夹树；PG 依赖不能省 |
| **B. 按 LocalMind 重写** | 坚持要"双击即用的桌面应用 + 零依赖安装 + 纯 Markdown 可迁移" | 后端要重写为 TS（SQLite/LanceDB），现有 FastAPI + pgvector 检索逻辑需移植 |

**我的判断**：如果目标是"自己长期用"，选 A——当前项目的数据层（pgvector 混合检索、父子检索、RAG 引用）已经踩完了坑，重写会把这些问题再踩一遍；只要补上「写入闭环」这 5 件事，它就能胜任。
如果目标是"做成给别人用的桌面软件"，选 B，但建议**先把 A 的第 1 批做完**，用它验证"编辑器 + 写回 + 软删除"的交互设计，再迁移——避免在新技术栈上重新设计产品。

> 无论选哪条路，**第一节的三个闭环**都是必须闭合的，与用什么框架无关。
