# 产品引导：KnowledgeHub

> 本文件是 Kiro Steering 的 **product.md**（产品引导），在每次交互中自动加载。
> 它定义产品的"为什么"——目的、用户、价值与边界。技术决策必须能回溯到本文档。

## 1. 一句话定义

**KnowledgeHub 是一款完全运行在个人电脑本地、面向单一使用者的个人知识库软件，通过 AI 与 RAG（检索增强生成）技术，把散落的个人资料变成可检索、可问答、可追溯的私有知识资产。**

## 2. 目标用户

| 维度 | 说明 |
|---|---|
| 用户数量 | **单用户**，即当前电脑的使用者本人 |
| 使用场景 | 个人学习、技术笔记、项目文档、毕业设计、面试复习、私人记录 |
| 技术水平 | 具备基本的电脑操作能力，能按中文教程启动软件；不假设会运维数据库或容器 |
| 使用方式 | 通过本机浏览器访问本地服务（`http://127.0.0.1:<port>`） |
| 账号体系 | **无**。不注册、不登录、无权限角色、无访客 |

## 3. 核心价值主张

1. **数据主权**：所有原始文档、解析文本、向量索引、会话与笔记默认保存在本地磁盘，不上传第三方。
2. **可追溯的 AI 问答**：AI 回答必须引用知识库中真实存在的原文，区分"原文 / 归纳 / 联网"三类来源，杜绝编造。
3. **知识闭环**：从"导入 → 解析 → 分块 → 索引 → 检索 → 问答 → 归档"形成完整链路，而不是只有一个聊天框。
4. **零运维依赖**：优先复用本机已有的存储与服务，避免引入 Docker、云服务等额外基础设施。
5. **长期可用**：关闭软件后数据仍在，重新启动后历史内容可恢复，适合长期积累。

## 4. 关键能力模块

### 4.1 核心闭环（本 spec 覆盖范围）

| 模块 | 能力概述 |
|---|---|
| **工程搭建与基础设施** | 前后端骨架、本地数据目录、PostgreSQL 数据库、配置管理、一键启动/停止、首次启动初始化 |
| **文档管理** | 多格式导入与解析、处理流水线与状态、预览/编辑/重命名/删除/导出、知识分类、标签 |
| **知识检索（RAG）** | 文本分块、向量嵌入、pgvector 索引、关键词（pg_trgm）+ 语义 + 混合检索、引用定位 |
| **AI 问答** | 模型配置（本地模型 / 外部 API）、上下文构建、引用生成、会话历史、多轮追问、三种输出模式、专属术语词典 |

### 4.2 后续扩展（本 spec 仅列路线图，不展开实现）

| 模块 | 能力概述 |
|---|---|
| **AI 知识加工** | 笔记整理与归档、标签推荐、冗余检测、跨文档知识关联、思维导图 |
| **学习辅助** | 模拟面试、评分与点评、错题管理、快捷复习（`/面试` `/错题` `/背诵` `/复习`） |
| **项目开发辅助** | 代码评审、故障排查、需求拆解、项目时间线 |

## 5. 业务目标

1. 让用户能够在**不依赖任何云服务**的前提下，长期、稳定地积累和管理个人知识。
2. 让用户能够用**自然语言**在个人知识库中找回、理解并应用已记录的知识。
3. 让 AI 的每一条知识性回答都能**点回到真实原文**，建立可验证的信任。
4. 让非技术用户也能通过**双击脚本**完成启动、使用与备份。

## 6. 非目标（明确"不做什么"）

以下内容**不在本项目范围内**，任何设计不得引入：

- ❌ 云端 SaaS、多租户、公网部署
- ❌ 账号注册、登录、权限角色、访客系统、公开分享页
- ❌ 多人实时协作
- ❌ 单纯的 AI 聊天机器人（无知识库、无检索、无引用）
- ❌ 自动把用户文档上传到第三方服务
- ❌ 遥测、埋点、数据分析上报
- ❌ 强制依赖 Docker / 云数据库 / 消息队列等重型基础设施

## 7. 成功判据（验收口径）

一个交付物只有同时满足以下条件才算"成功"：

1. 能在个人电脑上正常运行，无须云服务器、域名或公网部署。
2. 无须注册账号或搭建多用户系统。
3. 用户文档和知识索引默认存储在本地。
4. 能真正完成文件导入、解析、检索和 AI 问答。
5. AI 回答能引用真实知识库来源，引用可点回原文。
6. 支持笔记归档、面试、错题和项目开发辅助（核心闭环先落地，扩展后续补齐）。
7. 关闭软件再重新启动后，正式数据仍然保留。
8. 模型未配置时，非 AI 功能仍然可以使用。
9. 提供可实际执行的启动、测试和备份恢复命令。
10. **所有核心能力必须落到真实代码、实际数据读写和可验证的运行结果上**——不得用系统提示词、模拟数据或静态界面冒充功能实现。
