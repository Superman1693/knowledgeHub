# KnowledgeHub · 本地个人知识库 AI 平台

一款**完全运行在个人电脑本地**的个人知识库软件。通过 AI 与 RAG（检索增强生成）技术，把散落的个人资料变成**可检索、可问答、可关联、可复习、可追溯**的私有知识资产。

> 不是云端 SaaS，不是多人协作平台，也不是单纯的 AI 聊天机器人。
> 所有数据默认保存在本机，不上传第三方。

## 一、功能总览

### 知识管理
| 能力 | 说明 |

| 导入文档 | 拖拽上传 md/txt/pdf/docx/代码文件，后台自动解析、分块、向量化 |
| 网页剪藏 | 粘贴 URL 自动抓取网页正文、转 Markdown 存为文档，保留标题与来源地址；同一网址重复剪藏会提示 |
| 新建笔记 | 应用内 Markdown 编辑器（分栏/编辑/预览），支持 Ctrl+S 保存、粘贴截图 |
| 多级文件夹 | 树形分类，支持嵌套；删父分类时子分类自动上提，文档不变未分类 |
| 标签 | 多标签、标签筛选、AI 推荐（词频/对话模型）、相似检测与**一键合并** |
| 术语词典 | 自定义术语/缩写/项目名词及其别名，问答时优先采用 |
| 收藏 / 置顶 / 最近访问 | 常用笔记快速访问，工作台一屏总览 |
| 批量操作 | 文档列表勾选多篇 → 批量收藏 / 置顶 / 移动分类 / 追加标签 / 移入回收站（逐条返回成败） |
| 自动保存 + 冲突检测 | 编辑器 1.5s 防抖自动保存；正文被外部改动时以 409 + 并排对比拦住覆盖，**不静默丢内容** |
| 收集箱 | 未分类文档的暂存区，工作台显示「待整理」数量 |
| 回收站 | 删除 = 移入回收站，原文件与索引保留，可恢复或彻底删除；可设保留期（默认永不自动清理） |
| 版本历史 | 每次编辑自动快照，可查看 / **逐行对比** / 回滚到任意版本（回滚前自动备份当前版） |
| 速记 | `Ctrl+Shift+K` 随时记一笔，直接落进今日笔记的「今日记录」小节；不必先想标题与分类 |
| 每日笔记 | 按日期自动创建 `YYYY-MM-DD.md` |
| 笔记模板 | 内置技术笔记/项目复盘/读书笔记/面试记录，新建时可选 |

### 搜索与检索
| 能力 | 说明 |
|---|---|
| 关键词检索 | pg_trgm 分词命中计数 |
| 语义检索 | pgvector 余弦距离 |
| 混合检索 | 关键词 α=0.3 + 语义 β=0.7 加权融合 |
| 重排序（可选） | LLM 对候选片段精排，设置页开关，默认关闭 |
| 结果高亮 | 返回命中词列表，前端 `<mark>` 渲染 |
| 排序 | 相关度 / 更新时间 / 创建时间 + **更新时间区间筛选** |
| 拼音检索 | 只记得读音时可直接打拼音：全拼（`shujuku`）与首字母（`sjk`）都能命中中文 |
| 拼错容错 | 英文打错一个字母也能搜到（`vuee`→vue）；**仅精确检索结果不足时启用**，不污染正常搜索 |
| 标题检索 | 文档标题同样参与关键词与拼音匹配（按名字找资料），标题命中权重高于正文偶遇 |
| 全局快捷搜索 | `Ctrl+K` 全局搜索 + 跳转 + 快捷操作 |
| 筛选 | 分类 / 标签 / 视图（全部/收藏/置顶/最近/我的笔记） |
| 保存的检索条件 | 常用检索（关键词/模式/标签/日期区间）一键存为「智能集合」，随时重跑 |

## 三、快速启动

### 1. 初始化数据库（只需一次）

```bash
psql -h 127.0.0.1 -p 5432 -U postgres -f scripts/init_db.sql
```

### 2. 配置环境变量

```bash
cp .env.example .env
# 编辑 .env，填入 DB_PASSWORD（kh_app 的密码）
```

### 3. 启动

```bash
python scripts/run.py
# 或 Windows 双击 scripts/start.bat
```

### 4. 访问

- 前端：http://127.0.0.1:5173
- 后端接口文档：http://127.0.0.1:8000/docs

## 四、核心概念

### 三个闭环
| 闭环 | 链路 |
|---|---|
| **写入** | 新建/编辑笔记 → 写回磁盘 `.md` → 分块 → 向量化 → 可检索 |
| **关联** | 笔记 → `[[双链]]` → 反向链接 → 知识图谱 → 发现关联 |
| **复习** | 阅读笔记 → 生成闪卡 → SM-2 间隔复习 → 掌握沉淀 |

### 数据存哪里
| 内容 | 位置 |
|---|---|
| 笔记正文 | `data/documents/<uuid>.md`（Markdown，可直接用编辑器打开） |
| 附件 | `data/attachments/{images,documents}/` |
| 模板 | `data/templates/*.md` |
| 导出 | `data/exports/*.zip` |
| 备份 | `data/backups/*.zip` |

笔记正文以 **Markdown 文件** 保存在磁盘上——数据库存的是元数据和索引，Markdown 才是知识本体。删除应用后 Markdown 文件仍然可读。

## 五、测试

```bash
cd backend
python -m pytest tests -v --basetemp=.pytest_tmp
```

当前基线：**190 passed, 3 skipped**。

> `--basetemp=.pytest_tmp` 不是可选项而是**本机必须加的参数**：
> 本机把 `%TEMP%` 下的目录纳入「安全删除」保护，pytest 清理旧的临时目录时
> 会触发 `SAFE_DELETE_BULK_CONFIRM_REQUIRED` 并**中断整个测试进程**，
> 表现为「跑到一半没有汇总输出」。把临时目录固定到项目内即可绕开
> （`.pytest_tmp/` 已加入 `.gitignore`）。
>
> 3 个 skipped 是**刻意的守卫**，不是没写完：
> `test_scan_reports_orphan_file` / `test_mass_orphan_registration_is_capped`
> 在 `data/documents` 有残留文件时跳过（避免把残留当未收录文件导入知识库）；
> `test_backup_restore_roundtrip_and_orphan_cleanup` 在库中有数据时跳过
> （需在空库环境单独跑一次才算真正验证过恢复往返）。

## 六、已知限制

- **中文检索**：优先使用 `jieba` 精确分词（已装则自动启用），未安装时回退「中文 2-gram + 英文整词」分词后 pg_trgm 命中计数。
- **拼音检索**：依赖 `pypinyin`（未装则功能关闭，其余检索不受影响）。全拼与首字母分别存在 `chunks.pinyin` / `chunks.pinyin_initials`，
  由建索引时写入、首次迁移回填；**重建索引后拼音列才会更新**。已知局限：极少数英文词本身能切成合法音节（如 `shining` = `shi`+`ning`），
  会被当成拼音而多召回一些中文结果——刻意不为此引入英文字典，代价远大于收益。
- **拼音列只存中文部分**：标点会切断拼音连续性，纯英文若进拼音列会让 `shi` 命中 `shining` 造成假阳性，
  因此 `pinyin_of` 只取中文语素的拼音（「Vue3 响应式」的拼音列只有 `xiangyingshi`）。
- **网页剪藏只抓公开网页**：对所有目标（含**每一跳重定向**）做 SSRF 校验，
  拒绝内网 / 本机 / 云元数据地址（`127.0.0.1`、`192.168.*`、`169.254.169.254` 等），
  只放行 http/https 与常见 Web 端口。这是刻意的——该功能让服务端替用户访问外部 URL，
  不做管制就成了探测内网的跳板。
  已知限制：① 正文提取是启发式的（未引入 readability，环境未装），
  对结构规范的站点效果好，**纯前端渲染（SPA）页面取不到正文**；
  ② 图片保留为远程链接、**不下载到本地**（原站删图后链接会失效）；
  ③ 需要登录才能看到的页面取不到。
- **局域网访问需同时设口令（强制）**：默认只监听 `127.0.0.1`，仅本机可访问。
  要让手机等设备访问需改 `BACKEND_HOST=0.0.0.0` **并**设置 `ACCESS_TOKEN`；
  只改前者后端会**拒绝启动**（fail-closed）——知识库里是私人资料，
  裸奔在局域网上不可接受，这层校验不交给"记得去设"。
  口令以请求头 `X-Access-Token` 传递（浏览器直接开 `/docs` 时可用 `?token=`）；
  前端首次遇到 401 会弹框让用户填入，存 localStorage。
  注意：口令是明文传输（HTTP），**仅适用于可信局域网**；跨公网请自行加 HTTPS 反代。
- **对话与嵌入可分离**：可以是不同服务；`EMBEDDING_BASE_URL` 留空则复用对话服务。
- **嵌入维度**：`EMBEDDING_DIM` 必须与嵌入模型实际输出一致，修改后需重建全部索引（首次迁移也读该配置，保证列维度与模型一致）。
- **推理模型**：思考过程与正文分离展示，不计入回答与引用。
- **PDF 批注只支持有文本层的 PDF**：批注的锚点建立在「能划词」之上，
  没有文本层就没有坐标与引文，只能画框——扫描件请先走 OCR（见下条），
  或按文本笔记阅读。这是刻意的取舍，不是待办。
- **PDF 批注不参与向量语义检索的单独建库**：批注本身不写 `chunks`、不建向量，
  而是**导出成普通 `.md` 笔记**后参与检索。这样检索/双链/复习三条链路**一行代码都不用改**，
  是刻意选的路径；代价是「导出」这一步要用户主动点一下。
- **引文匹配不是 100%**：PDF 文本层抽取可能有断字差异（如 `re-\nsponse`）。
  已做规范化（去软连字符、折叠空白、去行尾硬连字符），仍匹配失败时
  会**显式标注「定位可能已失效」**并保留引文供检索，绝不静默丢弃用户的高亮。
- **PDF 扫描件**：无文本层时**自动尝试 OCR**（RapidOCR + PyMuPDF，纯 pip 安装、无需 Tesseract；可用时按可用性降级到 pytesseract）。OCR 引擎均不可用时才保持「需 OCR」的提示。
- **二进制格式不回写**：编辑 PDF/DOCX 只更新库内正文，不改原文件（防止损坏）。
- **联网补充默认关闭**：开启后问答可临时选择联网；未取到结果时绝不标注 🌐。
- **批量收录有上限**：「扫描同步」的「一并收录未收录文件」单次最多 200 个，超过会明确拒绝——避免请求长时间挂起后中途失败留下半成品。分批处理或用「导入文档」页上传。
- **测试不隔离（重要）**：`backend/tests/` 直连真实数据库与真实 `data/` 目录，靠「用例自建自清」维持干净。
  因此：① 不要在有重要资料的库上跑测试；② 若文件删除被系统拦截（如 Windows 占用、安全软件），
  残留文件会堆在 `data/documents/`，此时依赖目录干净的两个用例会**主动跳过**而不是把残留文件导入知识库。
  彻底解决需独立的测试库与测试数据目录，属已知待办。

## 七、常见问题

**Q：启动报「数据库连接失败」？**
确认 PostgreSQL 已启动、`.env` 中 `DB_PASSWORD` 正确、已执行 `scripts/init_db.sql`。

**Q：文档一直是「失败」状态？**
多为嵌入模型未配置或不可用。配置好后在文档管理点「重建索引」。

**Q：在应用外改了 .md 文件怎么办？**
到工作台点「扫描同步」，系统会检测被外部改动的文件并重建索引。

**Q：删错了笔记怎么办？**
到「回收站」恢复。原文件与索引在软删除期间都保留。

**Q：怎么让某篇笔记不被 AI 搜到？**
在文档详情或编辑器里关闭「允许 AI 读取」。该笔记在检索阶段即被排除。

**Q：保存时提示「这篇笔记已被其它地方修改」？**
说明你用编辑器（VS Code / Typora 等）改过同一个 `.md`，或另一个标签页在编辑同一篇。
弹窗里会**并排显示**「你正在编辑的版本」与「库中最新版本」，你可以选择用最新版覆盖编辑器，
或保留自己的修改强制保存。这是刻意设计——**宁可让你选一次，也不静默覆盖掉另一份修改**。
（编辑器还有 1.5 秒防抖的自动保存，正常使用基本不会丢内容。）
